% 2.4 Доверительные отношения и аутентификация запросов
%   - Концепция Trusted Issuers: кто может запрашивать токены у системы

%   - Три способа получения публичных ключей (OIDC Discovery, JWKS endpoint, статические)

% 2.5 Механизм доставки данных авторизации
%   - Проблема: как доставить ключи и токены до 160 МКС без единой точки отказа
%   - Два варианта: sidecar-агент vs Kubernetes-оператор
%   - Обоснование выбора оператора:
%     * Reconcile-цикл каждые 30 сек
%     * AuthJwtConfig CR как декларативная спецификация
%     * Запись в K8s Secret — МКС читает файл, не делает HTTP-запросы
%   - Два режима получения токенов: через оператор (статические) и напрямую (динамические)
%   - Диаграмма доставки токенов оператором (mermaid)
%   - Таблица характеристик: TTL, частота обновления, тип токенов
%
% 2.6 Проектирование процесса ротации ключей
%   - Трёхшаговый алгоритм: создание нового ключа → swap → удаление старого
%   - Две паузы с ping-механизмом (10 пингов × ~1 мин)
%   - Почему не sleep: устойчивость к сбоям (отказ зоны, недоступность Vault, рестарт пода)
%   - Счётчик пингов в PostgreSQL — прогресс не теряется при рестарте
%   - ResolveStuckRotationsJob — автовосстановление зависших ротаций
%   - Ключевые инварианты (5 штук)
%   - SLO ротации: 30 минут
%   - Расписание по контурам (таблица)
%   - Диаграмма последовательности ротации (mermaid)
%
% 2.7 Межконтурное взаимодействие (Token Exchange)
%   - Проблема: разные ключи на контурах → токен одного контура невалиден в другом
%   - Механизм exchange: получение exchange-token (TTL 5 мин) → обмен в целевом контуре
%   - Exchange-клиенты: связь с исходным клиентом, копирование политик
%   - Два способа получения: через оператор (рекомендуемый) и через IAuthJwtClient
%   - Диаграмма межконтурной авторизации (mermaid)
%
% 2.8 Управление конфигурацией через IaC
%   - Terraform Provider (Go): CRUD для клиентов, политик, trusted issuers
%   - Terraform Module (HCL): auth-jwt-terraform как единый источник истины
%   - Почему Terraform: принят в компании, декларативный, рецензируемый, доступен для агентов
%   - Пример конфигурации клиента (листинг)
%
% 2.9 Подбор инструментальных средств
%   Единый раздел. Для каждого инструмента: зачем нужен, критерии, почему именно он.
%   - PostgreSQL: persistence, простые запросы, экспертиза, готовая инфраструктура
%   - Vault: хранение приватных RSA ключей, доступ только у auth-jwt, уже используется
%   - Dragonfly: распределённый кеш, почему не Redis, схема L1 (in-memory) → L2 (Dragonfly) → L3 (PostgreSQL)
%   - C#: стандарт компании, Microsoft.Authentication, развитая экосистема
%   - Go: для оператора и Terraform Provider, Operator SDK, kubernetes client-go
%   - Kafka + Outbox-паттерн: доставка событий в SIEM, гарантия доставки через PostgreSQL
%   - Quartz.NET: планировщик фоновых задач (ротация, метрики, event log)
%   - Архитектура типового МКС в компании (Model, Services, Worker, Migrator)
%   - Интеграционные тесты: Testcontainers (PostgreSQL, Vault, Dragonfly в контейнерах)
